# Phase 2 — UI Design Contract

> Visual and interaction contract for the Streamlit UI Shell. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Pre-validated source:** This contract formalizes the already-review-approved design spec in `files/HANDOFF_claude_code.md` §10.5 (UI/UX, /plan-design-review score 3/10 → 9/10) and §10.6 (DX, /plan-devex-review). Those decisions are **LOCKED** — this file makes them buildable and checkable. Requirement IDs covered: UI-01..07, DX-01..05.
>
> **Medium reality:** This is a **Streamlit** app, not React. Streamlit constrains styling. These are **layout / information-architecture / interaction-state / token** decisions, not pixel mockups. Tokens are expressed via `.streamlit/config.toml` theme keys + per-cell HTML/markdown where Streamlit allows, NOT a CSS design system.

## Spacing Scale

Streamlit owns most spacing via its layout primitives (`st.columns`, `st.container`, gap params, default vertical rhythm). The contract pins **logical spacing intent**, mapped to the multiple-of-4 scale and to the Streamlit knob that expresses it.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | CI mini-bar height; gap between a probability number and its CI bar beneath it |
| sm | 8px | Inline gaps within a status row (`glyph` ↔ `label` ↔ delta arrow); `st.columns(gap="small")` |
| md | 16px | Default element spacing; gap between the controls column and the main column (`st.columns(gap="medium")`) |
| lg | 24px | Section padding between hierarchy blocks (ballot → probs → bracket); `st.divider()` rhythm |
| xl | 32px | Layout gap between the trust badge / banner header strip and the body |
| 2xl | 48px | Major section break above the collapsed bracket |
| 3xl | 64px | Page-level top/bottom padding (Streamlit default container; do not override) |

Exceptions:
- **CI mini-bar = 4px tall** (xs) — intentionally thin; it lives directly under each number, never as a separate row.
- **Layout split:** two-column page, controls (left, ~1 unit) vs main (right, ~3 units) via `st.columns([1, 3])`. The **column order/content reorders by mode** (UI-01), not the spacing scale.

## Typography

3 type roles + the load-bearing **numeric** role. Monospace for ALL numbers is a hard token (UI-06, CLAUDE.md), not taste — probabilities and W-L records must align in columns.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body / table cell (text) | 14px | regular (400) | 1.5 | Team names, labels, banner copy. Streamlit default body. |
| Numbers (probs, records, counts, CIs) | 14px | regular (400) | 1.5 | **Monospace.** Every P(3-0)/P(advance)/P(0-3), every record, the sim count, the timer. Right-aligned in table columns. |
| Heading (section) | 20px | semibold (600) | 1.2 | "Recommended Ballot", "Per-team probabilities", "Your picks — status". `st.subheader`. |
| Display / hero number | 28px | semibold (600) | 1.2 | **Monospace.** The ballot's P(≥5) headline % (pre-stage) and the P(≥5)-from-here % (live). The one big number on the page. |

Weights: exactly **2** — regular (400) + semibold (600). No light, no bold-900.
Sizes: exactly **4** — 14 / 20 / 28 (+ the 14 numeric reuse). No `st.metric` mosaic of equal-weight cards (UI-06): the hero number is display-size; everything else is body/heading. Hierarchy over symmetry.

## Color

Status palette is the correctness-critical part and is **LOCKED** colorblind-safe: advanced = blue, eliminated = amber, **never red/green** (UI-06, CLAUDE.md). Color is **always** paired with a text label + glyph — color alone fails ~8% of men, so the glyph/label is the real signal and color is reinforcement.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0E1117` (Streamlit dark base bg) | Page background, table background |
| Secondary (30%) | `#1A1D24` / `#262730` | Controls column surface, cards, the collapsed-bracket container, banner strip |
| Accent (10%) | `#7C5CFC` violet (DEFAULT — confirm) | See reserved-for list below |
| Status: advanced | `#3B82F6` blue | `/ secured` and live-advancing teams. **Always** with the `o`/`/` glyph + text label. |
| Status: eliminated | `#F59E0B` amber/orange | `x dead` teams. **Always** with the `x` glyph + text label. |
| Warn (banner) | `#F59E0B` amber | The `⚠ Seeds are INFERRED` banner (`st.warning`) and `live odds off` info banner (`st.info` neutral) |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The primary `[Run ▶]` / `[Re-sim ▶]` action button (the one CTA per mode).
2. The hero P(≥5) number (pre-stage ballot headline and live from-here %).
3. The active segment of the Pre-stage / Live mode toggle.
4. Focus ring on the active input (Streamlit applies `primaryColor` here automatically).

Accent is **NOT** used for: status (blue/amber own that), CI bars, table headers, links, ordinary text, or secondary buttons.

**Destructive actions:** none in Phase 2. (Result-locking lands in Phase 4; the only "destructive-ish" action here is dismissing the seed banner via the "seeds confirmed" toggle, which is a confirmation, not a delete — see Copywriting.) Therefore **no red destructive color is introduced** — which also protects the "never red/green" status rule.

**Contrast:** body/number text ≥ 4.5:1 against its surface; CI mini-bars must be visible against the table background (use the status hue at full opacity for the filled portion, `#3A3D46` track for the remainder). The Phase 1 lesson stands: **ASCII-only glyphs** in any string that may hit a Windows cp1252 console (`o`/`x`/`/`, not `●`/`✓`).

## Copywriting Contract

All four interaction states are built **per feature** (UI-05). The table below is the canonical copy; the full per-feature state matrix follows.

| Element | Copy |
|---------|------|
| Primary CTA (Pre-stage) | `Run ▶` — runs the MC; sub-label/help: "~15s for 100k sims, no API key needed" |
| Primary CTA (Live) | `Re-sim ▶` — re-simulates conditioned on locked results |
| Empty state heading (main, pre-run) | `Set ratings, then Run.` |
| Empty state body | `First sim needs no API key — ~15s for 100k tournaments.` (Per-team probs show dashes `—`, never `0%`.) |
| Empty state (ballot panel) | `Run to see the recommended ballot.` |
| Empty state (live mode, no locks) | `Lock a result to go live.` |
| Empty state (bracket) | seeded Round 1 only (the `(seed, seed+8)` table), all later columns empty |
| Loading (run) | progress bar + live running `P(advance)` tally + chunk counter, e.g. `Simulating… 60,000 / 100,000` (NEVER a blank spinner) |
| Success (run) | fade in results + run stamp, e.g. `100k sims · 12.4s` |
| Error state (bad rating cell) | inline cell error on the `st.data_editor` cell; **block the run** — `Ratings must be numbers. Fix the highlighted cell, then Run.` |
| Error state (impossible lock — Phase 4 surface, copy reserved here) | reject with reason, do NOT silently accept: `Can't lock {A} vs {B}: they've already played (no rematches).` / `…{team} is already eliminated.` |
| Trust badge — gated state | `engine validated vs Valve rulebook unit tests — full backtest pending seed data` (see caveat below) |
| Seed banner (persistent, dismissable) | `⚠ Seeds are INFERRED — verify vs the official seed list before trusting outputs.` + a field-by-field reconcile diff; a **"seeds confirmed"** toggle dismisses it (DX-02) |
| Odds-off banner (fail-soft, info) | `live odds off (no ODDSPAPI_KEY) — using manual ratings` (one line, never a crash) (DX-06/ODDS-08 seam; banner shipped now) |

**TRUST BADGE WORDING — CORRECTNESS CAVEAT (do not drift):**
The Phase 1 Budapest backtest was **DEFERRED** (authoritative Valve seeds unsourceable; GATE-01/04/05). Therefore the badge MUST read **"validated vs Valve rulebook unit tests — full backtest pending seed data"** and MUST NOT read "validated vs Budapest backtest" or show a green ✓ "backtest passed". The badge's validated state is tied to **BOTH** (a) the backtest having actually run AND (b) seeds confirmed — neither is true yet in Phase 2, so the badge ships in its **caveated** form. (STATE.md 2026-05-29 user decision; ROADMAP Phase 2 SC#4; HANDOFF §10.5 trust-badge + the Pitfall-6 "both, not one" rule.)

**Destructive confirmation:** none in Phase 2 (no delete/destroy actions). The "seeds confirmed" toggle is the only state-flipping control and is a positive confirmation, not destructive — no modal needed; it simply dismisses the banner and is the gate that (with the absent backtest) the trust badge reads.

### Per-feature interaction-state matrix (UI-05 — build ALL of these)

| Feature | Loading | Empty (pre-run) | Error | Success / partial |
|---------|---------|-----------------|-------|-------------------|
| Run sim (10–30s) | progress bar + live sim count + settling `P(advance)` tally (fed by `run_mc_progressive` Partials) | `Set ratings, then Run. First sim needs no API key — ~15s.` (never blank) | bad rating cell → inline cell error, **do not run** | fade in; `100k sims · 12.4s` |
| Per-team probs | skeleton rows | dashes `—`, NOT `0%` | — | number + always-visible inline CI mini-bar (monospace, right-aligned) |
| Ballot panel | `computing…` | `Run to see the recommended ballot.` | — | A vs B side by side, differing picks highlighted; P(≥5) hero (Phase 3 fills content; panel shell + states ship now) |
| Live status | re-sim spinner | `Lock a result to go live.` | impossible locked pair → reject + reason | `o live` / `x dead` / `/ secured` + P(≥5)-from-here delta arrow (Phase 4 fills; states reserved) |
| Bracket | — | seeded R1 only | — | record-bucket columns; locked/real solid, simulated faint |

## Layout & Information Architecture (medium-specific, UI-01)

Two explicit modes via **`st.segmented_control`** (DEFAULT — confirm; `st.radio(horizontal=True)` is the locked-in fallback) at the top: **Pre-stage** ↔ **Live**. Same data; the **main column reorders** by what matters per mode.

```
PRE-STAGE                                   LIVE (priority flips)
+- controls -+ +- MAIN -------------+        +- controls -+ +- MAIN ----------------+
| ratings    | | (1) RECOMMENDED    |        | round ▾    | | (1) YOUR PICKS-STATUS |
|  data_edit | |     BALLOT         |        | lock R2:   | |  /secured GamerLegion |
| S  slider  | |   A: max E[correct]|        |  GL | NRG  | |  x dead  B8           |
| N  input   | |   B: max P(≥5)     |        |  …         | |  o live  HEROIC       |
| [Run ▶]    | |   (P(≥5) = HERO)   |        | [Re-sim ▶] | |  P(≥5 here) 58% (HERO)|
|            | | (2) PER-TEAM PROBS |        |            | | (2) delta probs       |
|            | |     16 rows + CI   |        |            | | (3) BRACKET           |
|            | | (3) bracket(collap)|        |            | |                       |
+------------+ +--------------------+        +------------+ +-----------------------+
```

**Information hierarchy:**
- **Pre-stage:** Recommended ballot (HERO) > per-team probs (16-row dense table + CI bars) > bracket (collapsed in an `st.expander`).
- **Live:** locked-pick status + P(≥5)-from-here (HERO) > delta probs > bracket.
- The ballot headline / live headline is the **P(≥5) percentage** at display size (28px monospace, accent).

**Header strip (both modes, persistent):** trust badge (caveated) + `⚠ Seeds INFERRED` banner (until "seeds confirmed") + `live odds off` info line when no key.

**Loading UX (UI-03, the design×eng seam):** on a cache miss, drive `st.progress` by iterating `run_mc_progressive` directly — each `Partial(done, total, running_p_adv)` advances the bar and updates the running tally. Serve the cached `run_mc` `Result` on a hit. **Do not re-chunk** in a way that changes `n_chunks=20` or Phase 1 reproducibility breaks (Phase 1×2 seam).

**Cache key (UI-02, the Phase 2×4 seam — correctness-critical):** `@st.cache_data` keyed on `(ratings, S, N, locked)`. `locked` MUST be in the key NOW even though the locking UI is Phase 4 — omitting it makes Phase 4 a re-architecture and silently serves stale pre-lock distributions in live mode (Pitfall 13).

**Bracket (UI-04 in Phase 4 substance; shell-aware now):** record-bucket **columns** (`0-0 → 1-0 / 0-1 → … → 3-0 adv / 0-3 elim`), HLTV/Liquipedia convention — **NOT a tree** (Swiss teams reconverge by record). Locked/real solid, simulated faint. CONFIRMED against the live in-game Pick'Em.

**CI mini-bars (UI-04):** every probability cell renders the number **plus** a thin (4px) always-visible inline Wilson/epistemic bar beneath it. **Never** hidden behind hover/expand — that visibility IS goal G4 ("don't be falsely precise") made visual.

### Out of scope (design, §10.5 — do not build)
Responsive / mobile / tablet (local single-user desktop). Theming / light-mode toggle. Animations beyond state transitions. Branding.

## Open Items for Orchestrator Confirmation

These three were the ONLY genuinely-open items (everything else is locked by §10.5/§10.6/CLAUDE.md). `AskUserQuestion` is unavailable in this subagent, so prescriptive defaults were chosen and flagged — the orchestrator should confirm or override:

1. **Accent color** — DEFAULT `#7C5CFC` violet. Rationale: must avoid blue/amber (status semantics) and red (the "never red/green" rule, which also rules out Streamlit's default `#FF4B4B`). Alternatives: teal `#16B8A6`, magenta `#E0509E`.
2. **Mode toggle widget** — DEFAULT `st.segmented_control` (best mode-switch affordance, matches the §10.5 mockup). Fallback: `st.radio(horizontal=True)`. Both are explicitly sanctioned in §10.5.
3. **Base theme** — DEFAULT `base = "dark"` (dense monospace tables + colored CI bars read best on dark; matches esports tooling). Alternative: light (retune CI/status for ≥4.5:1 on white).
