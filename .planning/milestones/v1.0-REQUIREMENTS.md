## Engine (Swiss correctness core)

- [x] **ENG-01**: Round 1 pairings as seed N vs seed N+8, from the single seed→team map (no second hardcoded copy)
- [x] **ENG-02**: Rounds 2+ group active teams by (wins, losses) record and seed within group by Difficulty Score descending then initial seed ascending, via a single code path (no `if round == 2` special case)
- [x] **ENG-03**: Difficulty Score = `Σ(opp.wins − opp.losses)` over played opponents (NOT `Σ opp.wins`)
- [x] **ENG-04**: Within-group pairing uses rematch-avoiding high-vs-low fold; the fold sorts on the difficulty-ranked order, not raw seed
- [x] **ENG-05**: When no rematch-free perfect matching exists, pairs the least-disruptive rematch and logs a warning instead of crashing
- [x] **ENG-06**: A match is Bo3 iff either team is at 2 wins or 2 losses; otherwise Bo1
- [x] **ENG-07**: No pair plays twice within a stage; teams terminate at 3 wins (advance) or 3 losses (eliminated) with final record recorded
- [x] **ENG-08**: Engine accepts `locked: dict[frozenset({id,id}) -> winner_id]` and uses locked winners deterministically, respecting locked history in the no-rematch rule
- [x] **ENG-09**: RNG injected as a `seed` param threaded through the MC, using `numpy.random.SeedSequence.spawn` so reproducibility survives chunked execution

## Monte Carlo runner

- [x] **MC-01**: Runs N stage simulations (default 100k) tallying per-team count of 3-0, advance (any 3-W), and 0-3
- [x] **MC-02**: Outputs per-team P(3-0)/P(advance)/P(0-3) with Wilson confidence bands
- [x] **MC-03**: Probability invariants hold every run within tolerance (±0.05 at N≥50k): Σ P(3-0)≈2, Σ P(0-3)≈2, Σ P(advance)≈8
- [x] **MC-04**: Retains the full per-sim record sample (not just marginals) so the optimizer's P(≥5) and conditional re-sim can score against it
- [x] **MC-05**: Structured generator-first — yields incremental tally aggregates per chunk (e.g. 20×5k) to drive a progress bar — with a separate cached wrapper for the final result
- [x] **MC-06**: Series win prob uses closed-form Bo3 `p²(3−2p)` as a single Bernoulli draw (no 3-map sampling); Bo1 = `p_map`

## Probabilities & math

- [x] **PROB-01**: Per-map win prob `p_map(a,b) = 1/(1 + 10^(-(rating_a − rating_b)/S))`, S default 40, exposed as a slider
- [x] **PROB-02**: An odds-derived probability for an exact matchup is used directly as the series prob (Bo3 formula NOT re-applied)
- [x] **PROB-03**: Epistemic uncertainty modeled as an OUTER loop (sample p-vector from Beta(blend, var) per epistemic draw, run an MC batch per draw, aggregate across draws) — never folded into per-sim sampling
- [x] **PROB-04**: Beta method-of-moments fit clamps `variance < p(1−p)` before fitting so low-liquidity high-disagreement matches do not crash
- [x] **PROB-05**: Reported band = epistemic spread across draws (⊇ inner Wilson aleatoric band); a single source collapses the band to Wilson only

## Pick'Em optimizer (Valve binary)

- [x] **OPT-01**: Ballot A (greedy per-bucket marginal baseline): top 2 by P(3-0), top 2 by P(0-3), top 6 by P(advance) excluding the four chosen. Outcome: softened from "Max E[correct]" per Phase 3 V&V — the bucket-wise greedy maximizes the per-bucket marginal sum, not global E[correct]; kept as a transparent baseline, Ballot B (OPT-02) is the real P(≥5) recommendation.
- [x] **OPT-02**: Ballot B (P(≥5)-optimal) via hill-climb single-team swaps + re-bucketing moves scored by P(≥5) against the stored per-sim sample (no brute-force enumeration)
- [x] **OPT-03**: Both ballots valid (exactly 2/6/2, no team in two buckets) and reported side by side with differing picks highlighted
- [x] **OPT-04**: P(≥5/10) computed for the chosen ballot by scoring each simulated stage against it (hero number)
- [x] **OPT-05**: Correlated-pick warning surfaces when the two 0-3 picks meet in Round 1; Ballot B avoids the trap automatically

## Conditional re-simulation & live mode (killer feature)

- [x] **RESIM-01**: User locks actual results round by round; MC re-runs conditioned on standings/Buchholz/rematch history; re-sim fires via the cache key including `locked`
- [x] **RESIM-02**: Each locked pick shown as live / dead / secured with a P(≥5)-from-here delta (e.g. `71% → 58%`)
- [x] **RESIM-03**: An impossible locked pairing (rematch or already-terminated team) is rejected with a reason, not silently accepted
- [x] **RESIM-04**: Record-bucket bracket view (columns by W-L record, HLTV/Liquipedia convention — NOT a tree); locked/real results solid, simulated branches faint

## Odds ensemble (all three providers live)

- [x] **ODDS-01**: `OddsProvider` adapter interface (`get_quotes(matches) -> [OddsQuote]`) + `pool()`; OddsPapi (Pinnacle anchor), Polymarket, Kalshi all implemented live
- [x] **ODDS-02**: Per-source normalization — de-vig fixed-odds two-way; treat prediction-market price as ~probability adjusting only for spread/fees (routed on `vig_type`)
- [x] **ODDS-03**: Liquidity- and sharpness-weighted log-opinion pool → blended p + cross-source variance; weight by originate-vs-copy not headcount; OddsPapi soft-book bundle pre-pooled to ~one Pinnacle opinion
